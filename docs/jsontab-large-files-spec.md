# ТЗ на просмотр больших JSON и JSONL в jsontab

## Цель

Плагин jsontab для Total Commander должен открывать большие JSON и JSONL в Lister и показывать первые записи по мере загрузки. По завершении индексации пользователь получает полный список полей, а группировка и фильтрация работают по всему выбранному набору записей. Исходный файл остаётся на диске, значения загружаются по мере просмотра.

## 1. Режимы открытия и настройки INI

Перед загрузкой определить размер файла и выбрать режим. Настройки задаются в секции `[jsontab]` в байтах. Размер файла и два новых порога сравнивать как 64-битные целые числа.

| Настройки | Как открыть JSON или JSONL |
|---|---|
| Задан `full-load-max-size` | До указанного порога включительно загрузить файл целиком. При превышении открыть потоковый просмотр с фоновым построением индекса. Для выбора режима и открытия файла `max-file-size` игнорируется. |
| Задан только `max-file-size` | Использовать прежний режим полной загрузки с прежним ограничением. Файл больше положительного лимита отклоняется. Значение `0` сохраняет прежнюю полную загрузку без ограничения размера. |
| Оба ключа отсутствуют | Использовать порог полной загрузки **5 МиБ (5 242 880 байт)**. Файлы больше этого порога открывать по частям. |

Потоковый режим доступен только для чтения. В режиме полной загрузки действуют текущие представление и команды jsontab. `full-load-max-size` и `large-file-warning-size` принимают положительные целые значения. Пустое, некорректное или выходящее за допустимый диапазон значение обрабатывается как отсутствие ключа. Документация и пример INI должны описывать приоритет `full-load-max-size` над `max-file-size`.

Пример для существующего профиля с лимитом 10 МиБ.

```ini
[jsontab]
max-file-size = 10485760
full-load-max-size = 5242880
large-file-warning-size = 1073741824
```

При этих настройках файл размером 5 МиБ загружается целиком, а файл размером 20 МиБ открывается по частям.

### Диалог перед потоковой загрузкой

Диалог показывается, если уже выбран потоковый режим и размер файла достиг `large-file-warning-size`. Этот ключ задаёт порог предупреждения, а выбор режима определяет `full-load-max-size`. Значение по умолчанию — **1 ГиБ (1 073 741 824 байт)**. По результатам замеров решить, стоит ли снизить его примерно до 100 МиБ (104 857 600 байт).

> Размер файла — {размер}. Файл будет загружаться по частям. Пока идёт индексация, некоторые поля могут быть недоступны для группировки и фильтрации в таблице.

Диалог предлагает действия «Открыть» и «Отмена». Отмена завершает открытие до запуска индексации. Подтверждение открывает окно просмотра, а ход фоновой загрузки отображается в его строке состояния.

## 2. Первый проход — индекс записей и каталог полей

1. Открыть файл на чтение и зафиксировать его идентификатор и размер. Читать до этой границы блоками по 1 МиБ в фоновом рабочем потоке. Хранить байтовые позиции и номера записей в 64-битном представлении.
2. Для JSONL выделять значения по границам строк. Пустые строки пропускать. Учитывать LF, CRLF и последнюю валидную строку без перевода строки. Для JSON выделять элементы корневого массива или свойства корневого объекта потоковым разбором. Корневой скаляр показывать как одну запись. Между блоками сохранять состояние декодера и парсера, включая вложенность, экранирование и незавершённый символ.
3. Записывать во временный дисковый индекс пару `смещение, длина` для каждой принятой записи. Номер записи задаёт позицию в индексе. Смещение и длина считаются в байтах исходного файла. Корневой объект сохраняет представление `Attribute / Value`.
4. У записей-объектов собирать имена полей верхнего уровня. Каталог хранит имя, порядок первого появления и признак, что встретилось скалярное значение, включая JSON `null`. В `Grid` доступны все найденные поля, а в меню группировки — поля со скалярными значениями. Сравнение имён чувствительно к регистру.
5. Публиковать готовые строки и новые поля пачками. Добавлять столбцы справа по мере обнаружения, сохраняя выставленные фильтры, ширину и порядок существующих столбцов. Список полей и итоговое число записей считаются полными после успешного прохода до конца.

Потоковый режим рассчитан на синтаксически корректные файлы. При повреждении данных указывать место ошибки. Восстановление файла с ошибками по `parse-mode` остаётся возможностью полной загрузки. В потоковом режиме собирать поля по всему файлу. Настройка `skip-attributes-scan` продолжает действовать при полной загрузке. Поддержать текущее распознавание UTF‑8, UTF‑16 LE/BE и ANSI. Для неоднозначного файла без BOM разрешён перезапуск прохода с корректной кодировкой и сбросом промежуточного каталога. Границы записей должны оставаться корректными при смене блока и при многобайтных символах.

В памяти хранится каталог обычного размера. Для аномально большого числа уникальных полей предусмотреть ограниченную выдачу в интерфейс и хранение полного каталога или его части на диске. Обнаруженные поля должны оставаться доступны для выбора без повторного разбора исходника.

## 3. Подгрузка Grid, дерева и Text

- **Grid.** Использовать действующий виртуальный контрол. По номеру видимой записи фоновый читатель получает её диапазон из индекса, читает исходник и заполняет кеш. Стартовый размер страницы — до 256 записей. Это размер порции для таблицы. Блок чтения с диска остаётся 1 МиБ.
- **Кеш.** Стартовый бюджет — 32 МиБ для кеша значений вместе с его служебными структурами. Учитывать объём в памяти после декодирования. Вытеснять страницы, которые дольше всего не использовались. Удерживать видимую область и подгружать соседнюю порцию при наличии места. При резком переходе приоритет получает новая позиция. Повторные запросы одной страницы объединять.
- **Отрисовка.** При промахе кеша временно показывать `…`, а после получения данных обновлять нужные строки. Пропущенное поле показывать штатным обозначением. Отрисовка и прокрутка не ждут файлового чтения или очередного прохода.
- **Дерево и Text.** Узлы записей и групп подгружать по мере раскрытия. У корня и группы во вкладке `Text` показывать страницу записей с переходом между страницами. Отдельную запись показывать целиком, если она помещается в бюджет предпросмотра. Для записи, которая сама его превышает, показывать ограниченное превью и давать читать запись частями. Форматирование и подсветка применяются к показываемому фрагменту.

Декодирование и разбор необычно длинной записи должны укладываться в ограниченный рабочий объём. При индексации длинный токен пропускать или обрабатывать потоково с учётом его границ и синтаксиса. Значения для группировки и фильтров определять по исходным данным, включая часть за пределами превью.

## 4. Второй проход — группировка и фильтрация

| Действие | Что происходит |
|---|---|
| Группировка по выбранному полю | Фоновый проход извлекает значения выбранного поля и записывает на диск соответствия `ключ группы → номер записи`. Ключ различает отсутствующее поле, JSON `null` и строку `"null"`, а также числа, строки и логические значения. Массивы и объекты сохраняют текущее обозначение. |
| Открытие группы | Таблица запрашивает номера записей группы из дискового индекса. Значения читает через общий индекс смещений и тот же кеш. Записи внутри группы идут в порядке исходного файла. При большом числе уникальных групп список выдаётся страницами. |
| Фильтрация в Grid | Фоновый проход проверяет все записи текущего представления, включая записи вне кеша. Временный индекс результатов хранит номера совпавших записей. Фильтры используют действующие правила сравнения jsontab и применяются совместно. |
| Смена условия | Отменить прежний проход или отбросить его поздние результаты, если условие успело поменяться. Показывать, что число совпадений или состав группы уточняются, пока обработка не завершена. |

Группировку можно начать по полю, которое уже найдено. Новые записи продолжают поступать из первого прохода до зафиксированного конца файла. Итоговая группа учитывает все записи, даже если пользователь выбрал поле до завершения индексации. То же правило действует для уже выставленного фильтра. Если новое поле найдено позже, оно становится доступным без повторного открытия файла.

Временный индекс групп должен поддерживать постраничный запрос списка групп и их записей. Его реализацию можно выбрать отдельно, при условии что число записей и уникальных значений не заставляет хранить все ключи и соответствия в оперативной памяти.

Поиск через Lister и действующая навигация проверяются при приёмке. В потоковом представлении область поиска должна быть обозначена явно. Предлагаемый объём первой реализации включает поиск по текущему представлению и сохраняет порядок файла. Глобальную сортировку по столбцу можно вынести в отдельную задачу, указав это ограничение в интерфейсе потокового режима.

## 5. Состояние файла и ошибки

- Первый проход работает по снимку размера на момент открытия. При обновлении использовать прежний индекс и дочитать хвост, только если подтверждено дописывание. Незавершённую последнюю строку JSONL перечитать после дописывания. При замене, усечении или неоднозначном изменении файла перестроить индекс и сбросить кеш. Обычный JSON после изменения корневой структуры индексировать заново.
- При ошибке чтения, разбора или записи временных данных показать причину и позицию в исходнике, если её можно определить. Если ранее открытые записи ещё доступны, явно пометить их как частичный результат. Успешный проход публикует окончательное число записей и полей.
- При закрытии окна или отмене обработки остановить фоновые задачи и освободить временные данные. Результаты закрытого или заменённого источника не должны попадать в новое окно.

## 6. Приёмка и замеры

Для нагрузочной серии сгенерировать **два валидных файла по 1 ГиБ каждый**. Первый — UTF‑8 JSONL, второй — JSON-массив с теми же записями. Подобрать количество повторов и довести оба файла до точного размера валидными пробелами. Сохранить параметры генерации, ожидаемое число записей, известные группы и число совпадений фильтра. Синтетические данные должны содержать повторяющиеся и уникальные идентификаторы, поле ближе к концу файла, вложенные значения, Unicode и записи на границе блоков.

| Проверка | Ожидаемый результат |
|---|---|
| Порог по умолчанию | При отсутствии обоих ключей на 5 МиБ используется полная загрузка, на 5 МиБ + 1 байт включается потоковый просмотр. |
| Настраиваемый порог | С `full-load-max-size = 5242880` и `max-file-size = 10485760` файл на 5 МиБ загружается целиком, а файлы на 5 МиБ + 1 байт и на 20 МиБ открываются по частям. Изменение `full-load-max-size` сдвигает границу переключения. |
| Совместимость INI | При одном `max-file-size = 10485760` файл на 10 МиБ загружается целиком, файл на 10 МиБ + 1 байт отклоняется. При одном `max-file-size = 0` используется прежняя полная загрузка без проверки размера. |
| Предупреждение | При потоковом открытии файл размером ровно 1 ГиБ показывает диалог, файл ниже порога открывается без диалога. Проверить изменение порога предупреждения независимо от порога полной загрузки и отмену до начала индексации. |
| Первые данные и индексация | Первые строки видны до конца индексации. Ход загрузки отображается, а итоговые число записей и список полей совпадают с эталоном. |
| Навигация и кеш | Перейти в начало, середину и конец, затем несколько раз вернуться назад. Таблица и Text показывают ожидаемые записи, память кеша укладывается в бюджет. |
| Группы и фильтры | Группировка и фильтрация включают записи из начала и конца файла. Проверить редкое поле, различие отсутствующего поля, `null` и `"null"`, сочетание фильтра с группой и отмену устаревшего запроса. |
| Крайние случаи | На небольших отдельных образцах проверить длинную запись, границы блоков и кодировок, повреждённые данные, дописывание и замену файла. |
| Закрытие и повторное открытие | Фоновые задачи останавливаются, временные файлы освобождаются, результаты незавершённого прохода не появляются в следующем окне. |

Для каждого файла замерить время от подтверждения до первой отрисованной страницы, время полной индексации, время перехода в ещё не закешированный участок, время группировки и фильтрации, пик приватной памяти процесса и максимальный объём временных файлов. Указать версию Total Commander, сборку плагина и условия замера дискового кеша. В том же прогоне отметить время достижения первых 100 МиБ. По результатам сравнить JSON и JSONL и решить, достаточно ли данных, чтобы изменить порог предупреждения. Серия на 1 ГиБ подтверждает работу на этом объёме.
